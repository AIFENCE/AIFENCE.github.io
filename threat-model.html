Threat model

Trust boundaries and regression-backed controls for unauthorized, unaudited, cross-tenant, or tampered agent actions and handoffs.

#Security objective

AIFENCE prevents an AI agent or integration from converting untrusted/generated work into an unauthorized or unaudited downstream action, and prevents semantic handoff state from crossing tenant or protocol boundaries without enforcement.

#Trust boundaries

  1. Caller → composed API: API keys/mTLS establish identity; request-size and host/origin controls constrain ingress.
  2. Quality → Guard: admission quality never grants authority; Guard independently evaluates action, principal, environment and risk.
  3. Guard → Bus: only permitted Guard outcomes can create a fence handoff.
  4. Tenant → tenant: Bus workspaces and identity state are tenant-scoped.
  5. Wire → implementation: Bus wire v2 is validated against the frozen protocol/TCK contract.
  6. Runtime → evidence: audit events are hash-chained and signed without copying artifact contents into fence-completion events.

#Residual risk

AIFENCE cannot prove that external tools, models or downstream agents behave correctly after authorized execution. Operators still need to protect infrastructure credentials, configure tenant policy correctly, secure database/KMS infrastructure, and evaluate model-specific prompt/tool risks.
