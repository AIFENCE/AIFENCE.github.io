Security model

Shared identity, content classification, evidence, controlled egress, and an intentionally fail-closed posture.

#One identity model

The fence, Quality endpoints, operator console and Guard surfaces use Guard-backed identity rather than parallel weaker credentials.

SurfaceAuthentication posture
/health/live, /health/readyProbe endpoints
/metricsPrivate by default; production private metrics require a strong bearer token unless explicitly made public
/v1/fence/submitAPI key with decision-write authority
/v1/quality/*API key
/v1/console/*API key with read authority
/guard/*Guard router-level authentication

#Fail-closed posture

  • Guard is always fail closed.
  • Unknown policy constraints fail closed.
  • Database/audit/signing failures fail closed where they are part of the governed contract.
  • Standby regions cannot silently assume durable-worker responsibility.
  • Unsafe production configuration is rejected at startup.

Read exact failure semantics →

#Tenant and wire boundaries

Fence Bus workspaces are tenant-specific, idempotency is bound to sender/receiver/payload digest, and wire v2 is validated against a frozen TCK before semantic expansion.

#Evidence

Fence completion appends a tamper-evident fence.completed audit event containing artifact digest—not artifact contents—plus Quality, Guard and Bus decision metadata.

#Network controls

Outbound calls use HTTPS-only destinations, canonical path confinement, DNS revalidation/IP pinning, preserved TLS identity, no redirect following, controlled egress and bounded response sizes.

The repository maps priority threats to explicit controls and regression/conformance coverage.
