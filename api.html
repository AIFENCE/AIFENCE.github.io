API reference

The composed OpenAPI 3.1 surface: fence flow, Quality, Guard, Bus and operator endpoints.

The authoritative contract is the composed application's /openapi.json when documentation is enabled. The documented snapshot contains 165 endpoints.

#Fence flow

| Method | Path | Purpose | | --- | --- | --- | | POST | /v1/fence/submit | Run an artifact through Quality → Guard → Bus. |

#Quality

| Method | Path | Purpose | | --- | --- | --- | | GET | /v1/quality/controls | List quality controls. | | POST | /v1/quality/evaluate | Run the quality gate. | | GET | /v1/quality/registry | Quality-control registry summary. |

#Console

| Method | Path | Purpose | | --- | --- | --- | | GET | /v1/console/status | Operational status across every fence tier. |

#Guard resource groups

Guard exposes endpoints beneath /guard/v1/* for agents, API keys, approvals, artifacts, audit anchors/checkpoints, budgets, capabilities, decisions, delegations, dispatch, events, executions, incidents, memory, operator posture, policies, protocols, providers, tenant lifecycle, tools, traces, workload identities and more.

#High-value Guard endpoints

| Method | Path | Purpose | | --- | --- | --- | | POST | /guard/v1/decisions | Render an enforcement decision. | | POST | /guard/v1/capabilities | Issue exact-action capability. | | POST | /guard/v1/capabilities/consume | Consume a capability. | | GET | /guard/v1/approvals | List human approvals. | | POST | /guard/v1/approvals/{approval_id}/decision | Decide an approval. | | POST | /guard/v1/policies | Publish policy. | | POST | /guard/v1/policies/simulate | Simulate policy. | | POST | /guard/v1/policies/{policy_id}/activate | Activate policy. | | POST | /guard/v1/tools/{tool_id}/execute | Execute an authorized tool action. | | GET | /guard/v1/audit/verify | Verify audit chain. |

#Bus resource groups

Bus exposes endpoints beneath /bus/v1/* for durable handoff, acknowledgements, semantic state, content-addressed refs, learned patterns, protocol conformance, federation, calibration, routing, integrations, evaluations and economics benchmarks.

#High-value Bus endpoints

| Method | Path | Purpose | | --- | --- | --- | | POST | /bus/v1/bus/handoff | Persist a durable handoff. | | GET | /bus/v1/bus/pull/{receiver} | Pull a claimable message. | | POST | /bus/v1/bus/{message_id}/ack | Acknowledge delivery. | | POST | /bus/v1/refs | Store content-addressed reference. | | POST | /bus/v1/refs/resolve | Resolve a reference under policy. | | POST | /bus/v1/routing/choose | Choose a route. | | POST | /bus/v1/evals/run | Run Bus evaluation. | | POST | /bus/v1/benchmarks/economics | Run economics benchmark. | | GET | /bus/v1/protocol/tck | Read protocol conformance kit. |

#API discovery

Use the live /openapi.json as the source of truth for generated clients and tooling. This site intentionally describes the high-value surfaces while the runtime contract carries every schema and endpoint.
