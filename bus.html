Bus tier

The semantic communication runtime — durable handoffs, content-addressed references, learned patterns, and minimum-sufficient state.

The Bus tier is the semantic communication runtime: durable tenant-scoped handoffs, content-addressed references, minimum-sufficient state and protocol-conformant cross-language transport.

#Durable delivery

text
handoff ──▶ pending ──▶ claimed ──▶ acknowledged
                          │
                          └─▶ lease expiry ──▶ claimable again

A handoff is committed before it is represented as delivered. Receiver knowledge advances after acknowledgement, so claimed-but-unacked work remains recoverable.

#Tenant isolation

The composed fence uses tenant-specific Bus workspaces. A receiving agent cannot claim another tenant's fence handoff merely by knowing the receiver name or message ID.

#Semantic state

Bus preserves minimum-sufficient state rather than replaying entire conversations. High-risk semantics—negation, amounts, identities, authorization, deadlines, environment markers, instructions and constraints—take the strict preservation path.

#Content-addressed references

Stored content uses SHA-256 identity while authorization/lifetime remain separate grants. Identical bytes can deduplicate without sharing authorization.

#Broker transports

Broker publication follows the durable commit and carries routing identity rather than semantic content. The database-backed Bus remains source of truth.

#Protocol and conformance

Bus uses aifence/0.2, wire version 2. Canonical JSON/MessagePack digests and valid/invalid behavior are governed by the shared TCK consumed by Python, JavaScript and Go.
