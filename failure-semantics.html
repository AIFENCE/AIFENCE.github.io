Failure semantics

Failure behavior is part of the AIFENCE security contract, not an incidental runtime detail.

#Default behavior

Component / failureDefaultReason
Quality admission timeout/unavailableFail closedUnvetted artifacts do not silently proceed
Guard timeout/unavailable/policy errorAlways fail closedAuthorization never degrades into authorization-by-absence
Bus persistence/handoff failureFail closedA receipt cannot claim a handoff that was not committed
Fence audit append failureFail closedA governed decision without its audit event is incomplete
Optional telemetry exporter failureDegradedTelemetry transport is not an authorization dependency
Optional broker fan-out failureDegraded / retryDatabase-backed Bus remains source of truth
Database unavailableFail closedIdentity, policy, audit and handoff state are unavailable
Signing/KMS unavailableFail closed where signed evidence is requiredUnsigned evidence cannot be represented as verified
Deep Quality runtime unavailableAdmission remains availableDeep evaluation is explicit, not an admission dependency

#Narrow fail-open exception

Only quality and bus may be deliberately named as advisory fence tiers. guard is rejected if present in AIFENCE_FLOW_FAIL_OPEN_TIERS.

#Receipt rule

A handed_off receipt means admission passed, Guard permitted the action, the Bus handoff was durably created, and the fence-completion audit event was appended.

Optional telemetry export and broker propagation are not part of that transactional success claim.
