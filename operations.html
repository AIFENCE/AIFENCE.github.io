Operations

Run the fence with operator status, health probes, Prometheus metrics, OpenTelemetry traces, and explicit degradation signals.

#Operator console

GET /v1/console/ renders an operator dashboard; GET /v1/console/status returns the same data as JSON. Both require decisions:read.

The console shows:

  • durable handoff counts by status;
  • approvals pending for the caller's tenant;
  • per-tier circuit breaker state;
  • composed subsystem status;
  • quality-control registry size;
  • configured Bus transport.

#Health probes

| Path | Use | | --- | --- | | /health/live | Liveness — is the process up? | | /health/ready | Readiness, region and accepts_writes. |

accepts_writes is the critical global-load-balancer signal in an active/standby deployment.

#Metrics

Prometheus metrics include shared HTTP counters/latency plus guard decision outcomes, capability/approval lifecycle, execution transitions, outbox backlog, dispatch/dependency latency, and audit-anchor events.

#Tracing

Setting AIFENCE_OTEL_EXPORTER_OTLP_ENDPOINT enables OpenTelemetry tracing for the application and SQLAlchemy. Health and metrics paths are excluded. Content payloads are not placed into span attributes.

#Reading a degraded run

  • degraded_tiers in the fence receipt names any tier that failed open.
  • final_outcome: "authorized_not_delivered" means authorization succeeded but transport did not persist a handoff.
  • 503 tier_unavailable means a fail-closed tier could not answer.
