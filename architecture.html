Architecture

How Quality, Guard, and Bus compose into one FastAPI control plane with one identity, database, audit chain, and telemetry pipeline.

AIFENCE is one FastAPI application built by one factory. It owns the shared foundation and then invites each installed subsystem to mount itself.

text
        ┌───────────────── aifence.app.create_app() ──────────────────┐
        │ middleware · error envelope · health · metrics · OpenAPI    │
        │ lifespan (bridged) · circuit breakers · identity            │
        └──────┬──────────────────┬───────────────────┬───────────────┘
               │ register()       │ register()        │ register()
        ┌──────▼─────┐     ┌──────▼──────┐     ┌──────▼──────┐
        │  quality   │────▶│    guard    │────▶│     bus     │
        │  (gate)    │     │ enforcement │     │  transport  │
        └────────────┘     └─────────────┘     └─────────────┘
               └──────────────── aifence.core ───────────────┘
          config · db (one Base/engine) · errors · middleware
                   metrics · telemetry · env helpers

#Why a shared core rather than a single monolith

The tiers share FastAPI, SQLAlchemy, Alembic, pydantic, cryptography and Prometheus, but their domain configuration and models are distinct. aifence.core owns only the cross-cutting infrastructure every tier uses, while each subsystem keeps its own settings, models and routers.

#The composition seam

aifence.subsystems defines a register(app, ctx) protocol and discovers installed subsystems in flow order (quality → guard → bus). create_app never imports a subsystem directly.

  • subsystems can be added or replaced without changing the factory;
  • the application runs with any subset installed;
  • each subsystem mounts its own router and wires workers into the shared lifespan;
  • SubsystemContext hands each subsystem the shared settings, engine and session factory.

#Mounted sub-applications

Guard and Bus are mounted as FastAPI sub-applications at /guard and /bus. They keep their proven internals and router-level authentication while sharing the core engine, declarative Base, and metrics registry.

#Lifespans are bridged

Starlette does not run a mounted application's lifespan. create_app enters every mounted lifespan through an AsyncExitStack, so HTTP clients, workers and storage clients start and stop as one unit.

#OpenAPI is combined

Sub-app paths would otherwise live only under their mounted OpenAPI documents. The factory folds them into the root document, rebasing paths and namespacing component schemas to avoid collisions.

#Native routers

Quality, the Fence flow and the operator console are composed directly onto the root application and are explicitly bound to the same identity model.

#One database, one migration history

Every subsystem declares its models against aifence.core.db.Base, so one Alembic history builds the entire schema and one connection pool serves every tier. A migration/model drift test prevents undeclared schema changes.

#Data flow

  1. Quality scores the artifact and emits a quality decision.
  2. Guard compiles baseline + tenant policy into an enforcement plan and exact-action capability.
  3. Bus durably persists the vetted payload as a claimable handoff, then optionally fans out to a broker.

Every step shares the request id, audit chain and telemetry established by the core.
