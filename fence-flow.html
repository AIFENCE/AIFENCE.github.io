Fence flow

The three tiers as one governed pipeline, with short-circuiting, resilience budgets, and one truthful receipt.

The fence flow is what makes AIFENCE one system rather than three services sharing a host. A single authenticated request runs through all three tiers in process and returns one receipt describing what each tier decided.

text
POST /v1/fence/submit
   │
   ├── quality gate ──── fails ──▶ blocked_by_quality   (guard never runs)
   │        │ passes
   ├── guard enforcement ─ denies ─▶ blocked_by_guard    (bus never runs)
   │        │ allows
   └── durable handoff ─── degraded ─▶ authorized_not_delivered
            │ delivered
            └──────────────────────▶ handed_off

#Outcomes

| final_outcome | allowed | Meaning | | --- | --- | --- | | handed_off | true | Passed every tier; a claimable message was persisted. | | blocked_by_quality | false | The artifact failed the quality gate. | | blocked_by_guard | false | Policy denied or required approval. | | authorized_not_delivered | true | Permitted, but transport was degraded. |

authorized_not_delivered exists so the receipt never claims a handoff that did not happen.

#The receipt

json
{
  "request_id": "req_…",
  "tenant_id": "ten_…",
  "allowed": true,
  "final_outcome": "handed_off",
  "degraded_tiers": [],
  "stages": {
    "quality": { "passed": true, "score": 100 },
    "guard": { "outcome": "allow", "matched_rule": "baseline:read-only-low-risk" },
    "bus": { "delivered": true, "message_id": "M…", "content_ref": "aifence:sha256:…" }
  }
}

#Resilience

Every tier is fail-closed by default: a tier that cannot answer within its latency budget causes 503 tier_unavailable. Repeated failures trip a circuit breaker and short-circuit the tier for a recovery window.

quality and bus may be configured advisory. Guard cannot — naming it as fail-open is rejected at startup.

#Grounding a submission

Supplying sources enables the quality tier's grounding check for the whole flow, so fabricated figures are stopped before enforcement.

#Relationship to the Guard API

| Endpoint | Use when | | --- | --- | | POST /guard/v1/decisions | You want an enforcement decision only. | | POST /v1/fence/submit | You want the full pipeline and a durable handoff. |
