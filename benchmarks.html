Benchmarks & adversarial evaluation

A detection system is described honestly by two numbers together: how much hostile behavior it catches, and how much legitimate work it breaks. Either alone is marketing. AIFENCE records both and provides a command that reproduces the evaluation.

bash
aifence-redteam                         # baseline
aifence-redteam --behavioural analysis # cross-tier detector
aifence-redteam --compare               # both + delta

#Why traces rather than requests

A compromised or drifting agent rarely reveals itself in one request. Scope creeps, claims contradict earlier observations, and output quality decays. The evaluation unit is therefore a multi-turn trace: a sequence of turns by one agent executed against an accumulating observation window.

Every attack trace begins with plausible behavior and degrades. An attack that looks malicious on turn one measures little about trajectory-aware controls.

#Benign traces are mandatory

A detector that refuses everything can claim 100% detection. The suite therefore includes legitimate work near the boundary — real deletes, customer PII, outbound calls, and documents discussing credentials/prompt injection without containing an attack.

#Metrics

MetricMeaning
Detection rateAttack traces stopped by any means, including the default hold.
Specific detectionAttack traces stopped because a detector fired — the honest detector number.
False-positive rateBenign traces hard-refused.
Hold rateBenign traces held for human approval: friction, not refusal.

#Current measured regression suite

Measured on 18 traces: 11 attack + 7 benign.

MetricBaselineBehavioral analysis
Detection rate90.9%100.0%
Specific detection81.8%90.9%
False-positive rate0.0%0.0%
Hold rate71.4%71.4%

The 71.4% hold rate is the main operational finding for the strict baseline: most production writes need a human. That is deliberate fail-closed behavior, but it is also measurable friction.

Important limitation: 18 traces is a useful regression suite and far too small to treat the percentages as population-level safety claims. The purpose is reproducibility and regression detection, not a universal guarantee.

#Policy profiles

With behavioral analysis enabled, the measured policy profiles are:

MetricStrictBalanced
Detection rate100.0%100.0%
Specific detection100.0%100.0%
False-positive rate0.0%0.0%
Held for approval71.4%14.3%

Balanced matches strict on the measured security outcomes while cutting approval friction from 71.4% to 14.3% — an 80% relative reduction in held benign traces.

This depends on behavioral analysis. Without it, Balanced misses an indirect prompt-injection trace carrying an innocuous payload — the kind of case Strict can stop only through blanket default hold rather than specific detection.

#Cross-tier behavioral detector

The detector emits integrity.behavioral_drift on a deliberately small signal set:

  • Persistent ungrounded assertion — repeated grounding lapses that accumulate across turns.
  • Sustained intent escalation — operation severity rising across a run.
  • Untrusted influence — a state change following attacker-controllable external content. Reading untrusted content alone is not flagged; acting afterward is the signal.

#Regression gate

bash
aifence-redteam --behavioural analysis \
  --max-false-positive-rate 0 \
  --min-detection-rate 100

CI also asserts that the baseline still misses at least one scenario. A suite the current implementation passes trivially demonstrates only that the suite is too easy.

#Extending the suite

  1. Keep attack scenarios inside approved scope long enough to exercise the detector instead of immediately tripping coarse scope enforcement.
  2. Keep benign scenarios realistic and close to trigger conditions, or the false-positive rate becomes meaningless.
